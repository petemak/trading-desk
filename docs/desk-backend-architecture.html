desk.system · server architecture

How the trading desk backend boots, and how a price reaches the browser

Three pieces live under src/clj/desk: a validated config map, a price-simulation Engine, and a Pedestal HTTP/WebSocket server. desk.system/new-system wires them together with component/using; this page walks through exactly how, and traces one tick from the engine's background thread out to a connected browser.

01The three moving parts

Only Engine and Pedestal are actual component/Lifecycle records. Config is a plain, already-validated map — Component treats any non-Lifecycle value as already started, so it needs no start/stop of its own.

Not a component

Config

desk.system / resources/config.edn
  • Aero-loaded, profile-aware map
  • Validated once against schema/Config (Malli) before the system is even built
  • Throws ex-info with a humanized error on a bad shape — the system never starts malformed
Lifecycle

Engine

desk.engine / defrecord Engine
  • Depends on :config
  • Owns prices, clients, running atoms + one daemon Thread
  • All four created in start, nilled in stop — no top-level state
Lifecycle

Pedestal

desk.server / defrecord Pedestal
  • Depends on :config and :engine
  • Owns runtime — the started Jetty server map
  • Routing + WebSocket wiring delegated to desk.service

02Wiring the dependency graph

component/using doesn't just document a dependency — it tells Component both the start order (dependencies first) and what to inject: the started value at :config is merged into the engine record before its start runs, and both :config and :engine are merged into the pedestal record before its start runs.

desk/system.cljnew-system
(defn new-system
  ([] (new-system (env-profile)))
  ([profile]
   (component/system-map
    :config (config profile)
    :engine (component/using (engine/new-engine) [:config])
    :pedestal (component/using (server/new-server) [:config :engine]))))

desk/system.cljfail-fast config validation
(defn validate-config ;; called before new-system exists
  [cfg]
  (if (m/validate schema/Config cfg)
    cfg
    (let [errors (me/humanize (m/explain schema/Config cfg))]
      (throw (ex-info (str "Invalid config: " (pr-str errors))
                       {:errors errors :config cfg})))))

04Runtime: how one price tick reaches a browser

Once running, the engine's thread and the WebSocket layer never call each other directly — they only ever touch the same clients atom of core.async channels, one per open socket.

desk/engine.cljthe loop that drives Figure 2's right lane
(defn- run-loop! [{:keys [prices clients running tick-ms]}]
  (while @running
    (Thread/sleep ^long tick-ms)
    (when @running
      (let [next (tick-prices @prices)]
        (reset! prices next)
        (broadcast! clients (pr-str {:type :tick
                                      :prices next
                                      :ts (System/currentTimeMillis)}))))))
desk/service.cljconnect / disconnect — the two arrows into the Engine lane
(fn [_req _response _ws-map]
  (let [send-ch (atom nil)
        cleanup! (fn []
                   (when-let [ch @send-ch]
                     (engine/unregister-client! engine ch)))]
    (ws/make-ws-listener
     {:on-connect (ws/start-ws-connection
                   (fn [_ws-session ch]
                     (reset! send-ch ch)
                     (engine/register-client! engine ch)
                     (async/put! ch (pr-str {:type :snapshot
                                              :prices (engine/snapshot engine)}))))
      :on-close (fn [_status-code _reason] (cleanup!))
      :on-error (fn [_cause] (cleanup!))})))

05Shutdown

Component stops nodes in reverse dependency order — Pedestal first, then Engine, then the (no-op) Config — so nothing is left trying to write to a socket or channel that's already gone.

Pedestal.stop calls http/stop on the Jetty runtime and nils it. Engine.stop flips running to false and interrupts the sleeping thread — the loop notices on its next wake and exits — then nils all four fields, leaving nothing but an empty Engine record behind.
